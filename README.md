# GLaDOS 每日随机签到（Tampermonkey）

安装文件：[glados-checkin.user.js](./glados-checkin.user.js)。不需要运行 Node 或 Bash，Node 仅用于开发测试。

## 安装与配置

1. 在 Chrome、Edge 或 Firefox 安装并启用 Tampermonkey。
2. 打开 Tampermonkey 管理面板，选择“添加新脚本”，删除模板，将 `glados-checkin.user.js` 的全部内容粘贴进去，然后保存。
3. 打开或刷新一个普通 HTTP/HTTPS 网页。在 Tampermonkey 菜单中确认“GLaDOS 每日随机签到”已启用。扩展需要允许在该网页运行脚本；如 Tampermonkey 提示启用用户脚本权限，按其提示设置。
4. 点击脚本菜单“设置 Cookie”，粘贴你自己的完整凭证，例如：

   ```text
   koa:sess=你的真实值; koa:sess.sig=你的真实值
   ```

   不要粘贴示例省略值，不要带 `COOKIE=`、引号或 `Cookie:` 前缀。脚本只保存这两个 Cookie 字段，保存在 Tampermonkey 的脚本存储中。不要把真实 Cookie 发给别人。

5. 默认是北京时间每天 10:00–15:00。如需修改，点击“设置时间段和 UTC 偏移”，输入：

   ```text
   10:00,15:00,480
   ```

   三项依次为开始时间、结束时间、UTC 偏移分钟。`480` 表示 UTC+8，`0` 表示 UTC。这里将你的“10:00–15:00 时区”理解为每天的**时间段**，另用 UTC 偏移定义日期和当地时间。固定偏移不会自动跟随夏令时，暂不支持跨午夜。

6. 等几秒后点击“查看今日状态和最近记录”，确认 Cookie 已设置、今日计划时间已生成。无需一直打开 GLaDOS 网站，但需要保持至少一个允许脚本运行的普通网页。

## 执行规则

| 情况 | 行为 |
| --- | --- |
| 当天首次在 10:00 前启动 | 在 10:00（含）到 15:00（不含）之间随机选择并保存一个时间 |
| 当天首次在 12:00 启动 | 在当前时间到 15:00 之间随机选择，避免把计划排到过去 |
| 已保存 11:30 的计划，12:00 才恢复浏览器 | 仍在时间段内，下一轮检查时执行 |
| 15:00 才打开或恢复浏览器 | 当天跳过，下一天重新生成计划 |
| 刷新页面、重启浏览器 | 保留当天计划和尝试记录 |
| 同时打开多个页面 | 通过标签页选主、心跳和占用标记协调执行 |
| 请求失败、超时、Cookie 失效 | 记录结果，当天不自动重试；请检查 GLaDOS 网站，必要时手动签到 |
| 修改时间段 | 未执行的计划重新生成；当天已有尝试记录则保留，不自动再次请求 |

脚本每 30 秒检查一次，也会在页面恢复、获得焦点、网络恢复时检查。后台限流会增加延迟，因此计划时间不是精确到秒的执行保证。发送前再次检查时间段，过期就跳过。

“每日一次”具体指每个配置日期自动尝试一次，并不保证每天成功一次。脚本在发送前保存尝试记录：即使请求超时，服务端也可能已经完成签到，因此不自动重发。如果发出请求时页面关闭，记录可能停留在 `pending`，请到网站确认。修改 UTC 偏移可能改变日期归属，建议配置完成后保持稳定。

## 浏览器运行限制

Tampermonkey 用户脚本依附于匹配网页运行。只有浏览器进程还在，但所有网页都已关闭、冻结或被丢弃，不能保证签到。浏览器新标签页、扩展管理页、`chrome://`、`edge://` 等内部页面不属于普通网页。电脑休眠和浏览器退出期间也不会执行。

可以保留一个普通网页，并在浏览器支持时将其加入内存节省功能的排除列表。安装后已经打开的网页需要刷新以注入脚本。如果必须做到“没有任何普通网页，只开着浏览器也能调度”，应改用独立浏览器扩展的后台定时机制；这不属于用户脚本能严格保证的范围。

多标签页协调是尽力防重。Tampermonkey 共享存储没有原子比较交换，极端并发、缓存延迟或页面冻结/恢复的竞争下不能证明严格只请求一次。不同浏览器、浏览器配置文件、脚本副本之间也不共享实时锁。不要同时开启多份此脚本；原有 cron 若还在运行，也会独立签到。

## 请求与记录

请求复用原 Bash 脚本的地址和请求体：

```text
POST https://glados.network/api/user/checkin
Content-Type: application/json;charset=UTF-8

{"token":"glados.network"}
```

使用 `GM_xmlhttpRequest` 的 `cookie` 选项传入凭证，设置原站 Origin 和 Referer，User-Agent 由浏览器提供。扩展会要求允许访问 `glados.network`。部分浏览器对特殊请求头有不同限制，推荐先在桌面浏览器验证。

响应分类（1.0.1）：HTTP 2xx 且数字 `code` 为 `0` 时，记录为 `success`（本次签到成功）。根据用户提供的实际响应，HTTP 2xx、`code: 1` 且 `message` 去掉首尾空白后精确等于 `Today's observation logged. Return tomorrow for more points.` 时，记录为 `already`（今日已签到）。两者均表示已确认当天签到完成，不会再自动请求。仅 `points: 0` 不能证明已经签到，也不会据此把失败判为成功。其他非零 code 记录为 `failed`，无法解析或缺少数字 code 记录为 `unknown`。首次成功的真实响应尚未提供，`code: 0` 的成功规则仍待真实账户验证。

每日记录保存在 Tampermonkey 脚本存储中，包含日期、计划时间、尝试时间、结果时间、状态、服务端消息，以及返回的 code 和 points（缺失时为 null）。保留最近 30 条结果摘要，菜单显示最近 10 条；控制台及系统通知显示中文状态。不会写服务器上的 `/root/glados_req_checkin.log`，不会保存完整响应或输出 Cookie。`pending` 表示尝试已登记但没有收到可记录的结束回调。浏览器未运行、全天错过时间段等没有发出请求的日期，不会凭空产生成功或失败的结果记录；这不是服务端完整签到日历。先在网页手动签到时，脚本要等到自己的计划请求返回后，才能确认并记录“今日已签到”。

升级时在 Tampermonkey 中编辑原脚本，替换为新的全部代码并保存，然后刷新正在运行脚本的网页。原 Cookie、设置和记录会保留。旧版本误标为失败的历史记录不会自动改写，升级也不会清除当天尝试标记或重新发起签到。

## 验证

```powershell
node --test tests/checkin.test.cjs
node --check glados-checkin.user.js
```

本地测试使用模拟时钟、共享存储、标签页及 HTTP 回调，覆盖时间边界、随机计划、跨日、重复触发、标签页接管及错误结果。没有真实 Cookie，未执行实际账户签到，也未在安装了 Tampermonkey 的浏览器中验证特殊请求头及系统通知。

参考：[Tampermonkey 请求 API](https://www.tampermonkey.net/documentation.php?q=GM_xmlhttpRequest)、[标签页 API](https://www.tampermonkey.net/documentation.php?q=GM_tabs)。
